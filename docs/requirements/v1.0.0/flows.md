# 业务流程 v1.0.0（以代码为准）

## 1. 登录页自动识别流程
1. content 脚本在 `document_idle` 注入，读取插件总开关 `extensionEnabled`；停用则不渲染。
2. 读取本地完整配置 JSON。
3. 用 `matchCurrentPage` 遍历项目 / 环境：host 去 `www.` 小写后相等或子域匹配，path 关键字对 `pathname+search+hash` 包含匹配。
4. 未匹配 → 不展示浮窗，结束。
5. 匹配 → 取该项目 / 环境与按 `order` 排序的字段；若全局 `showLoginAccountPanel` 为真则渲染浮窗。
6. 若该环境存在默认账号，按重试策略自动尝试填充（带 token 去重）。
7. 监听 `chrome.storage.onChanged`：配置或开关变化时重载。

## 2. 默认账号自动填充流程
1. 匹配环境后取唯一默认账号；计算去重 token `项目:环境:账号:url`。
2. token 未变更过则执行填充，否则跳过（防重复）。
3. 遍历 `input` 字段，解析选择器（密码字段可回退），按 `retryDelays` 等待元素。
4. 写入值并派发 `input`/`change`/`blur` 事件。
5. 失败信息写入浮窗状态文案。

## 3. 浮窗手动填充流程
1. 用户在浮窗某账号行点击「填充」。
2. 逐字段解析选择器并按重试策略定位元素。
3. 写入 `input` 字段值并派发事件。
4. 就近 toast 提示「已填充账号」或错误信息。

## 4. 输入框账号选择器流程
1. 全局 `showAccountPickerOnInputClick` 为真。
2. 用户点击「已配置选择器的 input」元素。
3. 在点击位置弹出账号选择浮窗（默认账号优先排序）。
4. ↑/↓ 移动高亮、Enter 选择、Esc 或鼠标移出关闭。
5. 选择某账号即按填充流程写入页面。

## 5. 字段复制 / 敏感显隐流程
- 复制：点击字段复制按钮 → 写入剪贴板（`navigator.clipboard` 优先，回退 `execCommand`）→ toast 提示。
- 显隐：敏感字段默认 `••••••`；点击眼睛临时显示，10 秒后自动恢复隐藏；可再次点击手动切换。

## 6. 登录页账号新增 / 编辑 / 删除流程
- 新增：点击「新增」→ 按项目字段生成表单 → 校验必填 → id 为空则生成 → `saveAccount` 实时写本地 → 若设默认则置唯一默认 → 刷新列表。
- 编辑：选账号「编辑」→ 修改字段值 / 备注 / 是否默认 → 校验 → 实时写本地 → 刷新。
- 删除：点击「删除」→ `confirm` 确认 → `removeAccount` 写本地 → 关闭弹窗 / 刷新。

## 7. popup 交互流程
1. 点击插件图标打开 popup，读取总开关、当前活动标签 URL、外观、匹配结果。
2. 顶部开关切换 `extensionEnabled`。
3. 展示「项目-环境」或「未识别此页面」；匹配时可新增账号、展开账号列表。
4. 账号行「填充」→ 向 content 发 `WAA_FILL_ACCOUNT`；「编辑 / 新增」→ 发 `WAA_OPEN_ACCOUNT_EDITOR`，由 content 打开浮窗编辑器。
5. 「管理面板」→ 新标签打开 `extension.html` 并关闭 popup。

## 8. 配置管理页打开流程
1. popup 点击「管理面板」→ `chrome.tabs.create(extension.html)`。
2. 页面加载读取本地完整配置并应用外观主题。
3. 侧边栏在七大模块间切换；任意写操作 `persist` 写本地并刷新状态文案。

## 9. 项目 / 分组 / 模板 / 字段 / 环境维护流程
1. 进入对应模块，按需过滤 / 搜索。
2. 新增 / 编辑 / 删除（删除带 confirm）/ 拖动排序。
3. 表单与业务校验（必填、唯一、依赖关系）。
4. 保存写入本地完整配置；项目 / 字段保存时账号 `values` 与字段集合对齐。
5. 状态文案 / toast 反馈结果。

## 10. 账号管理（配置页）流程
1. 进入账号管理，可按项目 / 环境 / 关键字过滤（关键字只匹配非敏感字段）。
2. 新增（预选上下文）/ 编辑 / 设为默认 / 删除。
3. 写入本地配置并刷新。

## 11. 完整 JSON 查看 / 编辑流程
1. 进入「配置导入导出」，默认只读展示当前完整 JSON。
2. 点「编辑」进入可编辑态，修改文本。
3. 点「保存配置」→ 解析 → 运行时规范化 → 严格校验。
4. 通过则写入本地、退出编辑态；失败列出 `path: message`，保留原有效配置。
5. 「刷新」重新格式化当前配置。

## 12. JSON 导入流程
1. 点「导入 JSON」选择文件。
2. 读取文本 → 解析 → 规范化 → 严格校验。
3. 通过则写入本地（覆盖），提示「已导入配置」；失败提示「导入失败：JSON 不合法」并列错误。

## 13. JSON 导出流程
1. 点「导出 JSON」打开导出对话框。
2. 选择导出的项目子集（默认全选，可全选 / 全不选）。
3. 若本地存在 MinIO 信息，选择是否包含 MinIO 配置。
4. 选择是否包含主题设置。
5. 生成 JSON Blob 下载为 `web-account-config.json`。

## 14. MinIO 配置与测试流程
1. 进入「数据同步」，填写 Endpoint / Bucket / Access Key / Secret Key / Path Prefix / Object Key（即时写本地）。
2. 勾选「启用 MinIO」。
3. 点「测试连接」→ 对对象 URL 发 HEAD；成功 / 失败 toast 提示；未启用则提示「未启用 MinIO」。

## 15. 远程 → 本地同步流程（cloudToLocal）
1. 已启用 MinIO。
2. 点「远程 -> 本地」。
3. GET 拉取云端完整 JSON。
4. 以 `cloudToLocal` 与本地按稳定标识增量合并：同 id 云端覆盖本地，本地独有保留，本地已删但云端有的账号被恢复。
5. 写入合并结果到本地，提示合并警告 / 成功。

## 16. 本地 → 远程同步流程
1. 已启用 MinIO。
2. 点「本地 -> 远程」。
3. 将本地完整配置 `PUT` 整体覆盖云端对象（本地删除反映到云端）。
4. 更新 `meta.lastSyncedAt` / `remoteRevision`，写回本地并提示「已同步到 MinIO」。

## 17. 登录页 /login 解密容错流程（page-guard）
1. `document_start`、MAIN world 注入。
2. 仅当路径匹配 `/login` 时启用。
3. 劫持 `window.CryptoJS`，对 `AES.decrypt` 打补丁：空密文 / ciphertext 类型错误时返回空 WordArray，其他错误照常抛出。
4. 兼容脚本后注入（getter/setter + 轮询，5s 超时）。
